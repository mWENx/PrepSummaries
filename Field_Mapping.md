# Field Mapping: Excel Data Pull → Briefing Template

This document maps columns in **Updated Data Pull Example.xlsx** to merge fields and sections in **FY26_New_Briefing_Template_MailMerge.docx**.

## Template Structure

The briefing document has these sections (top to bottom):

1. **Header** — Donor name, degrees, employer, title, location
2. **Development Contact** — Relationship manager name and phone
3. **Purpose and Talking Points** — Bullet list (mostly static template text)
4. **Biographical Notes** — AI-generated bullet points
5. **Giving Information and Capacity** — Ratings and giving history
6. **Recent Contacts** — Contact report entries

## Non-Merge-Field Sections

These template sections are **not** populated by simple mail merge fields:

### Preferred_Mail_Name (in Purpose section)

The text "Purpose is to establish relationship between «Preferred_Mail_Name» and new dean..." appears as **static text** in the template, not as a merge field. It corresponds to:

- **Excel column:** `Constituent: First Name (No Trustee)` (e.g. "Kaila")

This needs to be handled by find-and-replace rather than mail merge.

### Biographical Notes

The template has placeholder "Sample" bullets under **BIOGRAPHICAL NOTES**. These are generated by:

- Querying OpenAI with the donor's name for a web-searched biography
- Replacing the placeholder bullets with the AI-generated bullet points

No direct Excel column maps here — the donor's name from `Constituent: First and Last Name` is used as the search query.

### Recent Contacts

The template has placeholder entries:

```
<<Contact Report Headline>>
<<<Contact report text>>
```

These are built from **multiple Excel rows** sharing the same `Constituent: Donor ID`. Each row is one contact report. The relevant columns are:

| Excel Column | Used For |
|---|---|
| `Constituent: Donor ID` | Grouping rows by donor |
| `Contact Report Date` | Date shown in the contact entry |
| `Contact Report: Description` | Headline text (e.g. "Qualification Visit in Palo Alto") |
| `Contact Report: Contact Report Body` | Full contact report narrative |
| `Contact Report: Contact Report Author (User): Full Name` | Author attribution |
| `Contact Report: Purpose` | Type of contact (e.g. "Visit", "Meeting Request") |
| `Contact Report: Contact Method` | Method (e.g. "Visit", "Email") |

## Excel Columns Not Used in Template

These columns exist in the data pull but have no corresponding merge field:

| Excel Column | Notes |
|---|---|
| `Constituent: Lifetime Fundraising` | Different metric from `Lifetime New Gifts & Comm. Credit` |
| `Constituent: Amount of Most Recent Gift` | Not shown in template |
| `Constituent: Date of Most Recent Gift` | Not shown in template |
| `Constituent: Designation of Most Recent Gift: Designation Code` | Not shown in template |
| `McCormick Last Gift or Pledge Amount` | Amount is not separately shown; info string includes it |

## Field Name Conventions

The template uses Word mail merge `«»` delimiters. Some field names are **truncated** due to Word's merge field character limit:

- `McCormick_Lifetime_New_Gifts__Comm_Cre` → full: `McCormick Lifetime New Gifts & Comm. Credit`
- `McCormick_Last_Gift_or_Pledge_Informatio` → full: `McCormick Last Gift or Pledge Information`

Excel column names use `: ` separators (e.g. `Constituent: Job Title`), while merge fields use `_` underscores and drop the `Constituent: ` prefix.

## Flutter App Implementation

The Flutter app (`nps_app/`) implements this mapping across four service files:

### excel_service.dart

- **`DonorData`** now includes `donorFirstName` (for Preferred_Mail_Name), a `mergeFields` map (keyed by MERGEFIELD names), and a `contacts` list of structured `ContactEntry` objects.
- **`ContactEntry`** holds headline, date, body, author, purpose, and method for each contact report row.
- The `mergeFields` map keys match the exact MERGEFIELD names from the FY26 template (e.g. `Donor_Name`, `All_Degrees`, `McCormick_Lifetime_New_Gifts__Comm_Cre`).
- Money fields (`Lifetime_New_Gifts__Comm_Credit`, `McCormick_Lifetime_New_Gifts__Comm_Cre`) are formatted as `$X,XXX.XX`.
- Date fields are formatted as `MM/DD/YYYY`.
- `Primary_Relationship_Manager_Name` is set to empty string (not available in Excel data pull).

### docx_service.dart

Handles four distinct replacement strategies for the FY26 mail-merge template:

1. **MERGEFIELD replacement** — Finds Word complex field sequences (`fldChar begin` → `instrText MERGEFIELD` → `fldChar separate` → display text → `fldChar end`) and replaces the entire sequence with a single run containing the value, preserving the display run's formatting (font, color, size).

2. **Static text replacement** — `«Preferred_Mail_Name»` is embedded as literal text (not a MERGEFIELD). Replaced via cross-run text join-and-replace with the donor's first name.

3. **Bio notes replacement** — Finds paragraphs with `ListParagraph` style containing "Sample" text, removes them, and inserts new `ListParagraph`-styled paragraphs with AI-generated biography bullets.

4. **Contact reports replacement** — Finds `<<Contact Report Headline>>` (SectionHeading style) and `<<<Contact report text>>` placeholder paragraphs. Removes them and inserts real contact entries: headline paragraphs (with SectionHeading style) followed by body paragraphs.

### generator_service.dart

- Loads `assets/templates/FY26_Briefing_Template.docx` (the new template).
- Passes `mergeFields`, `bioNotes`, `contacts`, and `donorFirstName` to `DocxService.fillTemplate()`.

### Changes from old template

| Aspect | Old (Briefing_Template.docx) | New (FY26_Briefing_Template_MailMerge.docx) |
|---|---|---|
| Placeholder syntax | `{{placeholder}}` | Word MERGEFIELD complex fields |
| Field replacement | Text find-and-replace across runs | Parse fldChar begin/end XML sequences |
| Bio notes marker | `{{bio_notes}}` placeholder | "Sample" bullets with ListParagraph style |
| Contact reports | `{{recent_contacts}}` single text block | `<<Contact Report Headline>>` + `<<<Contact report text>>` pairs |
| Giving fields | `{{lifetime_giving}}` (Lifetime Fundraising) | `Lifetime_New_Gifts__Comm_Credit` (different metric) |
| McCormick data | Not present | McCormick-specific giving fields added |
| Rating | Not present | `University_Overall_Rating` added |
| First name | Not used | `Preferred_Mail_Name` static text replacement |

## LLM Provider Support

The app supports three LLM providers for biography generation. All use web search capabilities:

| Provider | Model | API Endpoint | Web Search |
|---|---|---|---|
| OpenAI | `gpt-4.1-mini` | `/v1/responses` | `web_search_preview` tool |
| Google Gemini | `gemini-2.0-flash` | `/v1beta/models/.../generateContent` | `google_search` grounding |
| Anthropic Claude | `claude-sonnet-4-6` | `/v1/messages` | `web_search_20250305` tool |

API keys are stored per-provider in SharedPreferences and persist when switching between providers.

### Works Cited / Source Attribution

All three providers return citation data alongside the generated biography:

| Provider | API-Level Citation Source | Data Available |
|---|---|---|
| OpenAI | `annotations[].url_citation` in output_text | URL, title, character offsets in generated text |
| Gemini | `groundingMetadata.groundingChunks[].web` | URL, title; `groundingSupports` maps text segments to chunks |
| Claude | `web_search_tool_result` content blocks | URL, title, full page_content (what was actually read) |

**Implementation:**

1. **Updated prompt** (`bio_prompt.dart`) asks the LLM to include inline citation numbers `[1]`, `[2]` in biography bullets and return structured sources with `index`, `title`, `url`, and `detail` (what was learned).

2. **Dual citation extraction** — Each service parses both:
   - The JSON `sources` array from the LLM output (has numbered indices matching bio text)
   - The API-level citation metadata from the provider's response format
   - These are merged and de-duplicated by URL (`BioPrompt.mergeCitations`)

3. **WORKS CITED section** — Appended at the very end of the generated document (after Recent Contacts). Each entry is formatted as:
   ```
   [1] Page Title
        https://example.com/article
        What information was drawn from this source
   ```

4. **Shared model** (`bio_result.dart`):
   - `Citation`: index, title, url, detail
   - `BioResult`: biography list + citations list
